# V6 ランキング連携のゲーム側実装記録

更新日：2026-09-11（UTC）

この文書は、V6で作成したゲーム側の準備と、まだ確認していない本番境界を分けて記録する。基本武器50種類・補助20種類・1,000組の内容はV5の実装をそのまま引き継ぎ、ランキング連携のために縮小しない。

## ゲーム側で実装した契約

1. 開始時にゲーム側で一意な `start_id` を作成し、同じ開始要求の再送では同じ値を使う。
2. 開始受付の応答からサーバー発行の `play_id` を受け取り、画面やローカルの番号で代用しない。
3. 結果確定時に `finish_game_play_v1` を一度実行し、その後に一つの `submission_id` で `submit_score_idempotent_v1` を実行する。
4. 応答喪失・一時的な通信障害では、保存した `submission_id`、`play_id`、得点、得点内訳、名前、ルール版を変更せず再送する。finish確認済みならfinishを重ねない。
5. 状態は `idle`、`submitting`、`submitted`、`retryable_failed`、`permanent_failed` で管理し、表示文章の解析で再送可否を決めない。
6. `ResultLedger` はゲーム内の `resultId` ごとに結果・部品の精算を一回に限定する。リタイア結果は部品・ランキング送信の対象外とする。

`ranking-manifest.json` には正式URL、`game_id`、代表slug、公開クライアント版、採点順序、受付RPC名、送信RPC名、対象終了種別を記録する。HTTPアダプターはSupabaseの公開キーだけを受け取り、サービスキーや秘密情報を読み込まない。RPCへ渡すJSONは共通規約のsnake_case名へ変換する。

## 保存・途中再開との関係

進行保存はv3へ移行し、v1/v2の名前・研究・部品・解放・旧記録を保持する。戦闘途中は別のrun saveへ、固定更新の安全境界で次を一体に保存する。

- 敵・敵弾・味方弾の位置、速度、寿命、発生元、命中履歴、敵固有タイマー
- 経験値、レベル、候補、選択番号、保留状態、引き直し・除外、配置・容量
- 目的別乱数、出現ディレクター、固定時計、入力台帳、結果集計
- 機雷・重力領域・子機・周回・予告など、次の更新結果へ影響する一時状態

書き込みは一時キーへ先に保存し、完全なJSONを確認してから正規キーへ反映する。正規キーが壊れていても一時キーが有効なら復元し、壊れた値は退避する。再開後は明示的な一時停止から始め、画面を読みながら戦闘時間を進めない。候補が表示中だった場合は同じ候補を復元する。

## 本番未確認・変更していない範囲

この工程では、実験場リポジトリの共通文書を設計根拠として参照したが、次は確認していない。

- 本番Supabaseのgame登録、RPC署名・返り値、認証、RLS、権限、受付側の再計算
- 正式URLへの配備、実験場トップ・初回・ベストランキングの表示
- iPhone Safari実機、VoiceOver、片手操作、発熱、長時間本戦

既定ゲートウェイは未設定状態で、ブラウザから自動的に本番へ接続しない。本番DB、受付処理、登録値、保護設定、実験場の有効化は変更していない。実際の接続・有効化は、差分・復旧手順・影響範囲を提示したうえで別途許可を受ける。
