文書バージョン: 1.0  
対象リポジトリ: `chameleonjp-lab/kakomare`  
対象公開先: GitHub Pages  
想定主要端末: iPhone Safari  
実装方針: 画像素材に依存せず、図形・線・光・文字・動きをコードで生成する  
実装PR上限: **3本**

この文書は、ChatGPT Workが実装を進めるための基準書である。判断に迷った場合は、場当たり的に機能を足さず、この文書に書かれた完成条件、範囲、優先順位を基準にする。

## 0. 実装担当者への最上位指示

1. ゲーム名は、画面、コード、文書、テスト、コミット、PRのすべてで **「カコマレ」** とする。
2. 外部作品の名称、固有名、説明文、画面構成、配色、武器名、敵名、画像、音、変数名を持ち込まない。比較文や「何かを再現した」という説明もリポジトリに残さない。
3. 実装は最大3本のPRで完成させる。検査失敗や軽微な修正のために新しいPRを作らず、同じブランチへ追加コミットして直す。
4. 各PRは、Draft状態で実装をまとめ、ローカル検査とGitHub Actionsがすべて成功してからレビュー可能状態にする。
5. `main`へのマージは行わない。PR作成までを実施し、マージ判断は利用者に任せる。
6. スマートフォンとパソコンでゲーム速度が変わらないようにする。描画回数ではなく、経過時間を基準に戦闘を計算する。
7. iPhoneで誤操作しやすい二重タップ、長押し、ピンチ、画面端スワイプを必須操作にしない。
8. 戦闘画面は1画面内で完結させる。戦闘中にページを上下左右へスクロールさせない。
9. 画像・テクスチャ・外部フォントがなくても完成する構成にする。必要な図形、背景、アイコン、粒、弾、敵、ボタン装飾はコードか自作SVGで生成する。
10. 実装量を増やすより、開始から結果まで壊れず遊べること、端末差が出ないこと、選択の意味が読めることを優先する。

# 1. 完成目標

「カコマレ」は、画面中央のコアを六方向から迫る敵から守りながら、六角形の装置へ武器と補助機構を取り付け、短時間で自分の防衛構成を完成させる全方位防衛ゲームとする。

利用者はキャラクターを移動させない。通常時は装置が自動で攻撃し、危険な方向だけ手動で狙う。敵を倒して成長すると、現在の構成に合う強化候補から1つを選ぶ。選んだ内容は、数字だけでなく、六角装置の形、攻撃の軌道、音、敵の動きに反映する。

完成版は、次の流れを中断なく実行できる状態とする。

`起動 → 名前入力 → ホーム → ステージ選択 → 3秒カウントダウン → 戦闘 → 強化選択 → ボス → 結果 → 再戦またはホーム`

完成版に含める内容は次のとおり。

- 通常ステージ3つ
- 無限モード1つ
- 武器8種類
- 補助装置6種類
- 通常敵8種類
- ボス3種類
- 戦闘中の強化選択
- 戦闘外の研究
- 名前、設定、進行、記録の端末内保存
- ホームと結果画面の共有ボタン
- カメレオンJPの実験場へのリンク
- スマートフォン縦画面、横画面、パソコン画面への対応
- 自動検査、GitHub Pages公開、公開後確認手順

# 3. ゲームの基本体験

## 3.1 1プレイの長さ

通常ステージは3分から4分で終わる。

| ステージ | 制限時間 | 主な目的 |
|---|---:|---|
| ステージ1「包囲開始」 | 180秒 | 基本照準、強化、ボスを理解する |
| ステージ2「断続波」 | 210秒 | 敵の役割に合わせて構成を変える |
| ステージ3「閉鎖環」 | 240秒 | すべての敵と最終ボスへ対応する |
| 無限モード | 制限なし | 完成した構成で記録を伸ばす |

ステージ1は最初から選べる。ステージ2はステージ1クリア後、ステージ3はステージ2クリア後、無限モードはステージ3クリア後に解放する。

## 3.2 1プレイ中の流れ

1. 3秒のカウントダウン中に、ステージ設定、音、描画用プール、敵データを読み込む。
2. 中央コアと基本武器1つで戦闘を開始する。
3. 敵を倒すと経験値を得る。
4. 経験値が一定量に達すると、戦闘速度を10%まで落として強化候補を3つ表示する。
5. 候補を1回タップして選ぶ。決定後、0.25秒以内に戦闘へ戻る。
6. 中盤から敵の種類、出現方向、攻撃方法が増える。
7. 最後にボスが出現する。
8. コアの耐久力が0になると敗北。ボスを倒すと勝利。
9. 結果画面で、得点、時間、敵数、武器別の働き、主な敗因、報酬を表示する。

## 3.3 利用者に考えさせること

戦闘中に考える内容は、次の3つへ絞る。

- どの方向を手動で優先して狙うか
- 新しい武器を増やすか、持っている武器を育てるか
- 六角形のどこへ補助装置を置き、左右の武器を強めるか

移動、回避、照準、能力発動、アイテム使用を同時に要求しない。

# 4. 戦闘画面と六角装置

## 4.1 戦場

- 戦場は中央コアを中心とした円形とする。
- 敵は円の外側から中心へ向かう。
- 外周を六つの方向に分ける。内部では `sector-0` から `sector-5` として扱う。
- 六方向は、六角装置の六面と対応させる。
- どの方向が突破されたかを結果画面で確認できるよう、方向別の被害量を記録する。
- コアは移動しない。
- 通常敵はコアへ接触すると1回だけ接触ダメージを与え、消滅する。
- 遠距離弾は目立つ輪郭と予告線を出す。自分の攻撃演出より常に前面へ描画する。

## 4.2 六角装置の面

六面は、武器面と補助面を交互に置く。

```text
          武器A
   補助C         補助A
   武器C         武器B
          補助B
```

- 武器面は最大3枠。
- 補助面は最大3枠。
- 補助面は、左右に隣接する2つの武器へ効果を与える。
- 空き面には薄い輪郭だけを表示する。
- 武器や補助装置を取得すると、その面が展開する短い動きを入れる。
- 面の位置は固定し、戦闘中に装置全体を回転させない。向きが変わると、どの装置がどこにあるか判断しにくくなるためである。

## 4.3 コアの初期値

| 項目 | 初期値 |
|---|---:|
| 最大耐久力 | 100 |
| 初期武器 | 連針砲 レベル1 |
| 武器枠 | 3 |
| 補助枠 | 3 |
| 候補の引き直し | 1回 |
| 候補の除外 | 1回 |
| 手動照準保持 | 指を離してから0.8秒 |

研究で増やせる最大耐久力と基礎攻撃力は、合計25%を超えないようにする。戦闘外の成長だけで勝敗が決まらないようにする。

# 5. 操作仕様

## 5.1 スマートフォン

通常戦闘で使う操作は、1本指のドラッグと1回タップだけにする。

### 手動照準

- 戦闘領域のどこからでも指を置ける。
- 指を18px以上動かした時点で照準操作を開始する。
- 指を置いた場所から現在位置までの方向を、狙う方向として使う。
- 指を離した後、0.8秒はその方向を維持する。
- その後は自動照準へ戻る。
- 指を置いた場所そのものを狙わせない。指で敵を隠しやすくなるためである。

### 強化選択

- 強化中は戦闘速度を10%へ落とす。
- 候補は3つまで。
- 候補全体を48px以上のタップ領域にする。
- 1回タップで選択する。
- 二重タップ、長押し、ピンチを使わない。
- 誤選択を避けるため、候補表示後150msは決定を受け付けない。

## 5.2 パソコン

- マウスの押下とドラッグで、スマートフォンと同じ照準操作を行う。
- `Esc`で一時停止する。
- 強化候補はクリックで選ぶ。
- キーボードだけでも、左右キーで候補移動、Enterで決定できるようにする。

## 5.3 ブラウザ操作との競合防止

- 戦闘領域だけに `touch-action: none` を適用する。
- ホーム、設定、ルール説明など、通常の文章画面には適用しない。
- 戦闘領域でテキスト選択、画像ドラッグ、長押しメニューを起こさない。
- ページ全体を強制的に拡大禁止へせず、戦闘外の文章は利用者が拡大できる状態を保つ。
- `100vh`だけに依存せず、`100dvh`と安全領域を使う。

# 6. 自動照準

自動照準は、単に最も近い敵だけを狙わない。優先度を数値化する。

```text
優先度 = 接近危険度 + 敵の役割補正 + 現在武器との相性 + 手動指定補正
```

初期の目安は次のとおり。

| 条件 | 補正 |
|---|---:|
| コアまでの残り時間が短い | 最大 +100 |
| 遠距離攻撃の予告中 | +45 |
| 周囲を強化する敵 | +35 |
| ボス | +30 |
| 手動照準方向の内側 | +80 |
| 武器の射程外 | 対象外 |

手動照準中は、狙った方向の扇形60度以内を優先する。扇形内に敵がいない場合だけ、通常の自動照準へ戻す。

1フレームごとに全敵を並べ替えない。一定間隔で候補を更新し、現在の対象が有効な間は維持する。

# 7. 成長と強化候補

## 7.1 レベルアップ

経験値の必要量は、次の式を初期値とする。

```text
次のレベルに必要な経験値 = 16 + 現在レベル × 9
```

通常ステージ1回で、平均12回から16回の強化選択が発生するように調整する。

## 7.2 候補の構成

毎回3候補を表示する。

- 最低2候補は、現在持っている武器または補助装置を育てる内容にする。
- 新しい武器または補助装置は、最大1候補までにする。
- 空き枠がない種類は候補へ出さない。
- 最大レベルの装置は候補へ出さない。
- 同一候補を同時に2枚出さない。
- 直前に見送った候補が、次回そのまま3枚とも再登場しないようにする。
- 3候補を構成できない場合は強化を開かず、経験値とレベルを消費しない。
- 新しい武器または補助装置を取得するときは、空いている面を選んで装着する。

## 7.3 候補の表示

候補には、名前だけでなく、選択後の変化を表示する。

例:

```text
連針砲 Lv2 → Lv3
威力 8 → 10
貫通 0 → 1
1秒あたりの基準攻撃力 48 → 60
```

表示項目は次の順にする。

1. 装置名とレベル
2. 何が起こるかを一文で説明
3. 変更前と変更後
4. 得意な敵を短く表示
5. 分岐がある場合は、もう一方との違いを表示

## 7.4 引き直しと除外

- 引き直しは、表示された3候補をすべて再抽選する。
- 除外は、選んだ1候補をそのプレイ中の抽選対象から外す。
- 使用回数は画面上に常に表示する。
- 連打で複数回消費されないよう、処理中はボタンを無効にする。

# 8. 武器仕様

数値は最初の調整値であり、検査結果に応じて変更してよい。ただし、役割を別物へ変えない。

武器はレベル1から5まで。レベル3とレベル5で、二つの発展先から一つを選ぶ。同じプレイ中に選び直せない。

## 8.1 連針砲

高速で細い弾を撃つ基本武器。盾の回数を削ることと、単体への継続攻撃が得意。

| 項目 | 初期値 |
|---|---:|
| 1発の威力 | 8 |
| 発射間隔 | 0.16秒 |
| 射程 | 560 |
| 貫通 | 0 |

発展先:

- 分散型: 発射方向を増やし、小型の集団へ対応する。
- 貫通型: 弾速、威力、貫通数を増やし、硬い敵へ対応する。

## 8.2 光路刃

狙った方向へ直線攻撃を出し、一直線上の敵をまとめて攻撃する。

| 項目 | 初期値 |
|---|---:|
| 威力 | 28 |
| 発射間隔 | 1.15秒 |
| 幅 | 18 |
| 貫通 | 無制限 |

発展先:

- 幅広型: 攻撃幅と残る時間を増やす。
- 反射型: 外周で1回から2回向きを変える。

## 8.3 連鎖導体

最初の敵から近い敵へ攻撃を移す。密集した小型敵が得意。

| 項目 | 初期値 |
|---|---:|
| 初撃威力 | 16 |
| 発射間隔 | 0.85秒 |
| 連鎖数 | 3 |
| 連鎖ごとの威力 | 前段の80% |

発展先:

- 多連鎖型: 連鎖回数を増やす。
- 終端破裂型: 最後の敵で小さな範囲攻撃を起こす。

## 8.4 群集弾

敵が多い位置を予測し、範囲攻撃を行う。

| 項目 | 初期値 |
|---|---:|
| 中心威力 | 36 |
| 発射間隔 | 1.45秒 |
| 爆発半径 | 72 |
| 着弾予告 | 0.45秒 |

弾は指定位置まで `projectileSpeed` で飛び、着弾の0.45秒前から予告円を表示する。予告中に接触判定は行わず、着弾時だけ範囲攻撃を行う。

発展先:

- 分裂型: 着弾後に小弾を三方向へ飛ばす。
- 残留型: 短時間の減速領域を残す。

## 8.5 周回刃

コアの周囲を回り、近づいた敵へ接触攻撃を行う。

| 項目 | 初期値 |
|---|---:|
| 刃の数 | 2 |
| 1接触の威力 | 20 |
| 周回半径 | 108 |
| 同じ敵への再命中間隔 | 0.45秒 |

発展先:

- 多刃型: 刃の数と回転速度を増やす。
- 外周型: 周回半径と刃の長さを増やす。

## 8.6 残響円盤

敵と外周で跳ね返る円盤を放つ。複数方向の敵へ継続して触れる。

| 項目 | 初期値 |
|---|---:|
| 威力 | 22 |
| 発射間隔 | 1.05秒 |
| 反射回数 | 3 |
| 同じ敵への再命中間隔 | 0.30秒 |

発展先:

- 反響型: 反射回数と速度を増やす。
- 軌跡型: 通過した場所へ短い攻撃線を残す。

## 8.7 反発輪

一定間隔でコアから衝撃波を出し、近い敵を押し戻す。

| 項目 | 初期値 |
|---|---:|
| 威力 | 14 |
| 発動間隔 | 2.8秒 |
| 最大半径 | 165 |
| 押し戻し距離 | 58 |

発展先:

- 強反発型: 押し戻し距離と威力を増やす。
- 遅延型: 押し戻し後に減速を付ける。

## 8.8 遠隔重力点

敵が密集する外周寄りの位置へ吸引点を作り、短時間だけ敵を集める。

| 項目 | 初期値 |
|---|---:|
| 発動間隔 | 6.5秒 |
| 継続時間 | 2.2秒 |
| 吸引半径 | 125 |
| 継続威力 | 5 / 0.25秒 |

安全条件:

- コアから180px以内には生成しない。
- 終了時に敵をコア方向へ放り出さない。
- 吸引終了時は、敵の進行速度を0.4秒だけ下げる。
- ボスは完全に移動させず、進行速度低下だけを適用する。

発展先:

- 長時間型: 継続時間と半径を増やす。
- 崩壊型: 終了時に範囲攻撃を起こす。

# 9. 補助装置仕様

補助装置はレベル1から3まで。左右の武器へ効果を与える。同じ効果は加算しすぎないよう、上限を設ける。

| 補助装置 | レベル1 | レベル2 | レベル3 | 上限 |
|---|---:|---:|---:|---:|
| 出力環 | 威力 +10% | +15% | +20% | 合計 +40% |
| 律動環 | 発射間隔 -8% | -12% | -16% | 合計 -30% |
| 分岐環 | 6回ごとに50%威力で再発動 | 5回ごと | 4回ごと | 追加発動は連鎖しない |
| 収束環 | 射程 +8%、弾速 +10% | +12%、+15% | +18%、+22% | 射程 +35% |
| 観測環 | 外殻・標識体・投下体・位相体への威力 +10% | +18% | +28% | 合計 +45% |
| 制動環 | 減速・押し戻し +10% | +18% | +28% | 合計 +45% |

補助装置の効果を受けている武器は、六角面の接続線を淡く光らせる。色だけでなく線の本数でも接続状態を表す。

# 10. 敵仕様

敵は、色だけで区別しない。輪郭、内部線、移動、出現音、予告表示を変える。

## 10.1 小片

- 標準的な敵。
- 接触ダメージ: 5
- 基準耐久力: 24
- 基準速度: 42px/秒
- 脅威費用: 1.0

## 10.2 針走り

- 細長い輪郭で高速移動する。
- 接触ダメージ: 4
- 基準耐久力: 14
- 基準速度: 82px/秒
- 脅威費用: 1.3

## 10.3 外殻

- 外側に厚い輪を持つ。
- 1回の被害を最大24に制限する。
- 接触ダメージ: 9
- 基準耐久力: 95
- 基準速度: 27px/秒
- 脅威費用: 2.2

## 10.4 格子盾

- 本体の外側に格子を表示する。
- 8回攻撃を受けるまで、本体へ被害が通らない。
- 範囲攻撃は1回として数える。
- 接触ダメージ: 7
- 基準耐久力: 38
- 基準速度: 38px/秒
- 脅威費用: 2.0

## 10.5 胞子体

- 倒すと小型2体へ分かれる。
- 分裂後の敵はさらに分裂しない。
- 接触ダメージ: 7
- 基準耐久力: 54
- 基準速度: 36px/秒
- 脅威費用: 2.6

## 10.6 標識体

- 周囲120px以内の敵の速度を20%上げる。
- 効果範囲を点線で表示する。
- 接触ダメージ: 6
- 基準耐久力: 48
- 基準速度: 34px/秒
- 脅威費用: 3.0

## 10.7 投下体

- コアから一定距離で停止し、1.1秒の予告後に弾を撃つ。
- 弾は自分の攻撃で破壊できる。
- 遠距離弾の威力: 10
- 基準耐久力: 42
- 基準速度: 31px/秒
- 脅威費用: 3.0

## 10.8 位相体

- 1.4秒ごとに、0.55秒だけ攻撃を受けない状態になる。
- 無効状態へ入る0.25秒前から輪郭を点滅させる。
- 接触ダメージ: 8
- 基準耐久力: 50
- 基準速度: 40px/秒
- 脅威費用: 3.2

# 11. ボス仕様

## 11.1 回転冠

ステージ1のボス。

- 三枚の盾が本体の周囲を回る。
- 盾の隙間へ攻撃を通す。
- 一定時間ごとに盾の回転方向が変わる。
- 30%耐久力を失うごとに、通常敵を一方向から追加する。
- 手動照準を使う意味を最初に理解させる。
- 内側の停止位置へ着いた後は、6秒間隔でコア向け攻撃を行う。
- 攻撃の0.9秒前から、コアとボスを結ぶ線を表示する。
- 攻撃は速度180px/秒、威力12、寿命1.3秒の破壊可能な弾とする。

## 11.2 群れの設計者

ステージ2のボス。

- 六方向のうち一方向を予告し、その方向へ小型敵をまとめて出す。
- 予告は1.5秒前に太い線と短い音で示す。
- 一度使った方向を連続して選ばない。
- ボス本体だけを狙うか、増援を減らすか判断させる。

## 11.3 反響核

ステージ3のボス。

- 一定量の攻撃を受けると、外周へ反射弾を準備する。
- 反射弾の方向を1.2秒前から表示する。
- 反射弾は破壊できる。
- 自分の攻撃演出で予告線を隠さない。
- 最終段階では、通常敵と反射弾が同時に出るが、同じ方向へ危険を集中させすぎない。

# 12. 敵の出現管理

固定の敵一覧を秒単位で大量に書かず、時間ごとの脅威量を使って出現させる。この値を **脅威予算** とする。

1秒ごとに脅威予算を追加し、敵ごとの脅威費用を消費して出現させる。

```text
1秒あたりの追加予算 = ステージ基礎値 + 経過秒 × 上昇値
```

初期値:

| ステージ | 基礎値 | 1秒ごとの上昇値 | 同時敵上限 |
|---|---:|---:|---:|
| 1 | 1.3 | 0.012 | 90 |
| 2 | 1.7 | 0.016 | 125 |
| 3 | 2.0 | 0.020 | 160 |
| 無限 | 1.8 | 0.018、5分ごとに増加 | 180 |

追加規則:

- 新しい敵は、最初に単独または少数で出して特徴を理解させる。
- 同じ方向から3回連続で通常出現させない。
- 方向集中の特別波は、1秒以上前に外周を光らせて予告する。
- ボス出現中も通常敵を完全には止めない。ただし表示上限を超えない。
- 表示上限へ達した場合は、新規出現を待たせる。既存敵の速度を上げて帳尻を合わせない。

ステージごとの導入順:

| 時間帯 | ステージ1 | ステージ2 | ステージ3 |
|---|---|---|---|
| 序盤 | 小片、針走り | 小片、針走り、外殻 | 小片、針走り、格子盾 |
| 中盤前 | 格子盾 | 胞子体、標識体 | 外殻、胞子体、標識体 |
| 中盤後 | 胞子体 | 投下体 | 投下体、位相体 |
| 終盤 | 混成 + 回転冠 | 混成 + 群れの設計者 | 全種類 + 反響核 |

# 13. 難易度と数値調整

## 13.1 敵の強化

通常ステージでは、経過時間に応じて耐久力をなだらかに上げる。

```text
敵耐久力倍率 = 1 + 経過秒 × ステージ係数
```

初期係数:

- ステージ1: 0.0030
- ステージ2: 0.0038
- ステージ3: 0.0045

敵の移動速度は、開始時から終盤まで最大25%増加にとどめる。速度を上げすぎず、主に敵の組み合わせと出現量で難しくする。

## 13.2 無限モード

- 5分ごとに区切りを入れる。
- 各区切りで敵耐久力 +22%、出現予算 +12%、ボス耐久力 +25%。
- 敵速度は合計 +40%で上限。
- 15分以降は敵数を増やし続けず、耐久力と特殊敵の割合を上げる。
- 端末負荷を難易度として使わない。

## 13.3 救済

- コア耐久力が30以下になると、耐久力回復を候補へ出せる。
- 回復量は20。1プレイで最大2回。
- 直近15秒で同じ方向から被害が集中した場合、次の通常出現でその方向の比率を少し下げる。
- これは完全な自動救済ではなく、理不尽な偏りを減らすためだけに使う。

# 14. 得点と報酬

## 14.1 得点

```text
得点 = 敵得点合計
     + 生存秒 × 5
     + 残り耐久力 × 20
     + ステージクリア加点
     + ボス撃破加点
```

- ステージ1クリア: +3,000
- ステージ2クリア: +5,000
- ステージ3クリア: +8,000
- ボス撃破: 各 +2,000
- 無限モード: 5分ごとに +5,000

同じ敵を大量に出して得点を稼ぐだけにならないよう、敵得点は脅威費用を基準にする。

## 14.2 部品

戦闘外の研究に使う通貨は「部品」だけにする。

```text
獲得部品 = 20 + 生存秒 ÷ 6 + ボス撃破数 × 25 + 初回クリア加点
```

敗北しても部品を得られる。繰り返し作業を強制しないよう、研究の総費用は通常プレイ15回から25回程度で主要項目を解放できる範囲にする。

# 19. 音の方針

外部音源へ依存せず、Web Audio APIで短い効果音を生成する。

必要な音:

- ボタン
- カウントダウン
- 通常射撃
- 重い攻撃
- 敵撃破
- 強化取得
- コア被害
- 危険予告
- ボス登場
- 勝利
- 敗北

同じ効果音を短時間に大量再生しない。同種の音は50msから100msの間隔でまとめる。

Safariでは、利用者の操作前に音を開始しない。最初の「ゲーム開始」操作でAudioContextを再開する。音の再開に失敗しても、ゲーム開始を止めない。

音楽は、短い低音と環境音を組み合わせた軽い生成音とする。処理負荷が高い場合は、音楽を停止して効果音だけ残す。

# 21. ゲーム状態

画面状態を明示して、二重開始や開始直後の一時停止を防ぐ。

```text
boot
→ name-entry
→ home
→ stage-select
→ preparing
→ countdown
→ playing
↔ upgrade
↔ paused
→ victory または defeat
→ result
→ home または preparing
```

規則:

- `countdown`中に敵を進めない。
- `playing`へ入る処理は1回だけ。
- `upgrade`中は入力先を強化画面に限定する。
- `paused`中はゲーム時間、敵、弾、効果音を止める。
- `result`へ入った後、衝突や得点を更新しない。
- 同じボタンを連打しても、状態遷移を二重実行しない。

# 22. 時間計算

端末の表示回数に関係なく同じ結果にするため、ゲーム内部を一定間隔で進める。これを固定時間更新とする。

- 基準: 1秒を60回に分ける
- 1回の内部更新: `1 / 60`秒
- 1描画で追いつく内部更新: 最大5回
- それ以上遅れた場合: 遅れを切り捨て、操作不能な追いつき処理を防ぐ
- 発射、移動、状態異常、出現、ボス攻撃は内部時間で計算する
- CSSアニメーションの終了を、戦闘判定の基準にしない

必須検査:

同じ乱数種と同じ操作記録を使い、60Hz相当、90Hz相当、120Hz相当、30Hz相当の描画入力でシミュレーションし、次を一致させる。

- 180秒時点の敵位置
- 発射回数
- 撃破数
- コア耐久力
- 得点
- ボス行動回数

小数誤差による座標差は許容するが、勝敗や回数は一致させる。

# 23. 乱数と再現性

各プレイに乱数種を持たせる。

```text
runSeed = ステージID + 開始時刻由来の値 + 連番
```

- 敵の出現方向
- 候補抽選
- 一部の攻撃位置

を同じ乱数生成器から取得する。

結果画面へ乱数種を表示する必要はないが、開発モードでは確認できるようにする。バグ報告時に同じ戦闘を再現できるよう、実行記録へ保存する。

本番画面から自由に乱数種を指定できる機能は付けない。

# 24. 当たり判定と大量表示

## 24.1 当たり判定

- 円、線分、扇形を中心に使う。
- 画像の透明部分を調べる当たり判定は使わない。
- 弾と敵を全組み合わせで比較しない。
- 戦場を区画へ分け、近い物体だけを比較する。

## 24.2 再利用

使い終わった敵、弾、粒を破棄して作り直さず、再利用する。これをオブジェクトプールとする。

対象:

- 通常敵
- 分裂後の敵
- 自弾
- 敵弾
- 爆発
- 被害数字
- 背景の信号点

## 24.3 表示上限

| 対象 | 標準上限 | 演出少なめ | 最小 |
|---|---:|---:|---:|
| 敵 | 180 | 160 | 140 |
| 自弾 | 280 | 220 | 180 |
| 敵弾 | 80 | 70 | 60 |
| 粒 | 500 | 260 | 100 |
| 被害数字 | 18 | 10 | 0 |
| 画面揺れ | 4px | 2px | 0px |

表示を減らしても、攻撃判定や得点を消さない。同じ位置の効果をまとめて描画する。

## 24.4 解像度

- 端末の画面密度をそのまま無制限に使わない。
- `devicePixelRatio`は最大2に制限する。
- 処理負荷が続いた場合は1.5まで下げられるようにする。
- CSS上の見た目サイズと内部描画サイズを分離する。

# 25. 自動的な演出調整

直近3秒の処理時間を測る。

- 平均が20ms以下: 設定どおり
- 20msを2秒以上超える: 粒と被害数字を25%減らす
- 28msを2秒以上超える: 解像度を下げ、背景点を止める
- 35msを1秒以上超える: 画面揺れと残像を止める
- 10秒安定した場合だけ、1段階ずつ戻す

ゲーム速度は変えない。敵や弾を遅くして端末差を隠さない。

自動調整が働いても、利用者が選んだ「最小」設定より演出を増やさない。

# 26. 保存仕様

データ量が小さいため、初回完成版は `localStorage`を使う。読み書きは必ず一つのサービスへ集約する。

## 26.1 保存形式

```text
{
  version,
  profile,
  progress,
  records,
  settings,
  statistics,
  updatedAt
}
```

必要項目:

- `version`: 保存形式の版
- `profile.name`
- `progress.unlockedStages`
- `progress.parts`
- `progress.researchLevels`
- `records.stageBest`
- `records.endlessBest`
- `settings.audio`
- `settings.effects`
- `settings.reducedMotion`
- `statistics.playCount`
- `statistics.clearCount`
- `statistics.totalKills`
- `statistics.weaponUsage`

## 26.2 保存時期

- 名前確定時
- 設定変更時
- 研究購入時
- 戦闘開始時にプレイ回数を加算
- 結果確定時
- ページを閉じる前

戦闘開始直後にプレイ回数を増やす。結果画面到達時ではない。

## 26.3 破損対応

- JSON解析失敗で白画面にしない。
- 破損データを別キーへ退避する。
- 初期値で起動し、「保存データを読み込めませんでした」と表示する。
- 設定画面から退避データをコピーできるようにする。
- 未知の項目は無視する。
- 旧版からの変換関数を用意する。

## 26.4 書き出しと読み込み

- JSON文字列として書き出す。
- 読み込み前に形式と版を検査する。
- 読み込み後に即上書きせず、内容の概要を表示して確認を取る。
- 不正値は上限下限へ丸めず、読み込み自体を拒否する。

---

# 27. 端末の中断と復帰

- `visibilitychange`で非表示になったら自動一時停止する。
- `pagehide`で保存する。
- 戻った際に黒画面のままにしない。
- WebGLの表示領域が失われた場合は、復元を試みる。
- 復元できなければ、現在のプレイを中断としてホームへ戻し、再戦ボタンを表示する。
- 中断で部品や得点を不正に確定しない。
- 音の再開に失敗しても、映像と操作は続ける。
- 画面の向き変更中は一時停止し、配置完了後に再開カウントダウンを出す。

# 28. 利用しやすさ

- 主要ボタンは最低48 × 48px。
- 文字は通常14px未満にしない。
- 重要な数値は16px以上。
- DOM上のボタンへ適切な名前を付ける。
- キーボードのフォーカス位置を見えるようにする。
- 色だけで状態を伝えない。
- 危険予告は、色、線、動き、音のうち最低二つを使う。
- 画面読み上げ用の領域へ、勝敗、耐久力低下、強化候補、結果を短く通知する。
- 動きを減らす設定を用意する。
- 音なしでも遊べるよう、すべての重要予告を画面へ出す。

- 自動照準の優先度
- 手動照準方向
- 武器の発射回数

- 格子盾の回数判定
- 胞子体の分裂上限
- 位相体の無効時間
- 遠隔重力点がコア近くへ出ないこと
- 得点
- 部品
- 保存と旧版変換
- 破損保存からの復旧

## 29.3 結合検査

- カウントダウン中に戦闘が進まない
- 開始直後に一時停止へ入らない
- 強化中に敵が通常速度で進まない
- 一時停止中に得点と時間が進まない
- 結果後に敵や弾が更新されない
- 戦闘開始時にプレイ回数が1増える
- 結果を二重保存しない
- 連打でステージを二重開始しない

## 29.4 画面検査

PlaywrightでChromiumとWebKitを使う。

主要経路:

1. 初回起動
2. 名前入力
3. ホーム
4. ステージ選択
5. カウントダウン
6. 戦闘
7. 強化
8. 一時停止と再開
9. 勝利
10. 敗北
11. 結果
12. 研究
13. 設定
14. 保存後の再読込
15. 壊れた保存データからの復旧

各画面で確認する内容:

- JavaScript例外0
- 未処理Promise拒否0
- 横スクロール0
- 要素重なりなし
- 主要ボタン48px以上
- 文字切れなし
- 結果画面が最上部
- 共有失敗時の代替表示
- 実験場リンクが正しい

## 29.5 長時間検査

自動シミュレーションで次を行う。

- 通常ステージを各100回
- 無限モードを30分相当
- 最大敵数、最大弾数
- 100回の再戦
- 画面回転を20回
- 一時停止と再開を50回

メモリ使用量がプレイごとに増え続けないことを確認する。

# 32. ChatGPT Workの進行規則

各PRで次の順序を守る。

1. `main`の最新状態を確認する。
2. この計画書を読み、対象PRの範囲だけを取り出す。
3. 対象外の将来機能を混ぜない。
4. 対象ブランチを1本作る。
5. まずデータ構造と状態遷移を決める。
6. 画面だけでなく、開始から結果まで通す。
7. ローカルで `npm run check`を成功させる。
8. Draft PRを1本だけ作る。
9. GitHub Actionsを確認する。
10. 失敗したら同じブランチへ修正を追加する。
11. 成功後、敵対的検証を行う。
12. 見つかった問題を同じPRで直す。
13. 再度すべての検査を成功させる。
14. PRをレビュー可能状態にする。
15. 利用者へ、変更、非変更、検査、未確認事項、実機確認項目を報告する。

新しいPRを作ってよいのは、前のPRが利用者によりマージされた後だけである。

# 35. iPhone実機の最終確認手順

自動検査成功後、iPhone Safariで次を順番に確認する。

1. 公開URLを新しいタブで開く。
2. 起動画面が8秒以内にホームまたは名前入力へ進む。
3. 名前を入力する。
4. ホームで「カコマレ」が読みやすく表示される。
5. ゲーム開始を押す。
6. 3秒のカウントダウン後、すぐ戦闘が始まる。
7. 画面の任意位置から指を動かし、手動照準できる。
8. 指を離すと自動照準へ戻る。
9. 強化候補を1回タップで選べる。
10. 一時停止し、再開できる。
11. 別アプリへ移動し、戻る。
12. 黒画面にならず、再開カウントダウンが出る。
13. 縦画面から横画面へ回転する。
14. 要素が重ならない。
15. 勝利または敗北して結果へ進む。
16. 結果画面が最上部から表示される。
17. もう一度を押す。
18. 3回以上連続で再戦する。
19. ホーム共有を実行する。
20. 結果共有を実行する。
21. カメレオンJPの実験場を開く。
22. Safariを再読込し、名前と進行が残ることを確認する。
23. 演出量を最小にして再戦する。
24. 音を0にして重要予告が画面だけで読めることを確認する。

問題が一つでもある場合、次のPRへ進まず、現在のPRブランチで修正する。
