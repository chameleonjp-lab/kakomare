# 競技型無限モードのルール契約（V7ゲーム側準備済み／本番未接続）

この文書は、後続工程が同じ条件を参照するための設計契約です。`expansion-v7-runtime` は本番ランキングを有効化する識別子ではありません。V6でゲーム側の保存・結果・送信アダプターとmanifestを準備し、V7で最終ゲートの戦闘検査を追加しました。実験場の実際の登録、RPC署名・返り値・認証・権限は未確認です。既定値は未設定ゲートウェイで、本番データベースや実験場設定へ接続・変更しません。

## 共通の開始条件

| 項目 | V5引き継ぎ案 | 意味 |
|---|---:|---|
| コア耐久 | 100 | 全員が同じ初期耐久で始める |
| 基準威力 | 8 | 研究購入量で変えない基準値 |
| 初期武器 | `needle` | 全員が同じ一つから始め、残りは戦闘中に抽選する |
| 初期武器枠 | 3 | 最初に同時稼働できる武器個体数 |
| 初期補助枠 | 3 | 最初に同時稼働できる補助個体数 |
| 初期稼働容量 | 6 | 武器・補助・発展が競合する試作値 |
| 引き直し | 2回 | 全員共通。実質同一候補は回数を消費しない |
| 除外 | 2回 | 範囲を明示して全員共通にする |

研究・通常ステージの解放・保存済みの武器解放は保持しますが、競技開始時の基礎能力・候補集合・引き直し・除外には適用しません。文字、音量、演出量など戦闘計算を変えない設定は使用できます。

## 候補抽選の重み

有効な候補集合を作り、以下の段階別重みで3枚を抽選します。重みは勝敗を均等化するための隠れ補正ではなく、候補の種類を偏らせないための公開データです。

| 候補の種類 | 重み |
|---|---:|
| newWeapon | 3 |
| existingWeaponGrowth | 5 |
| support | 4 |
| expansion | 2 |
| specialEvolution | 1 |
| continuousProgress | 1 |

レベル上限、前提、排他、空き枠、容量、同種上限、除外、実効値上限を確定前に再検証します。通常候補が1〜2枚ならそれを残し、不足分だけ継続候補で補います。完全に合法な特別発展がないとき、その名前だけを候補へ出しません。

## 得点・終了・同点

| 得点要素 | 係数 | 取り扱い |
|---|---:|---|
| 正規出現の敵を倒す | 10 | 同じ敵の終端を一度だけ加点 |
| 危険段階の突破 | 100 | 段階を一度だけ加点 |
| ボス突破 | 1000 | 同じボスを一度だけ加点 |
| 実際に達成した追加危険 | 250 | 選択だけでは加点しない |

生存時間と終了時HPは結果情報として保存しますが、待機や終了直前の回復を主な得点源にしません（`timeAndHpAreResultFields=true`）。敗北、記録確定終了、中断、破棄、試験結果を分け、V6で受付契約へ対応付けます。V7ではこの方針をBattleSceneの競技スコアへ適用し、整数の有限範囲と同点順序は最終公開前に変更記録へ固定します。

## 乱数と競技資格

乱数は `enemy-spawn`、`candidate-draw`、`combat-effect`、`presentation` に分けます。無効入力、画面再表示、演出設定、同一候補の引き直し失敗は、敵やボスの乱数を進めません。同じ開始条件・抽選規則で競いますが、全員へ同じ引きを配る固定シード競争へは変更しません。

競技資格は次のとおりです。

- 開始受付が発行したplay_idとルール版を保持する
- ランキング対象は研究・解放状況に依存しない共通初期条件で始める
- 候補・除外・引き直しは有効性を再検証してから確定する
- 終了種別と得点内訳を一度だけ確定し、同じ結果を再送しても増やさない
- V7ではゲーム側の送信契約と最終検査を準備するが、本番DB・受付・認証・権限は未確認のまま別許可へ分ける

## V7のゲーム側境界

V7のゲーム側は、開始再送用の`start_id`、受付が発行する`play_id`、結果送信用の一つの`submission_id`、finish→submitの順序、応答喪失後の同一内容再送、idle／submitting／submitted／retryable_failed／permanent_failedを実装しています。結果・精算台帳は一つの`resultId`を一回だけ反映し、リタイアをランキング対象へ送りません。`ranking-manifest.json`の正式URL・game_id・版・採点順序を検証します。V7の最終ゲートでは、競技スコアへ生存時間・残HPを加算せず、通常モードの旧式得点とはルール版を分離します。

実際のSupabase／実験場の受付、登録値、認証、権限、iPhone Safari、公開配備の一致は未確認であり、ユーザーの別許可なしに有効化しません。採点係数はV1の比較案を出発点とし、V4以後の本戦データで変更する場合は旧値・新値・理由・版を残します。
